# RandomBench plan

This is how RandomBench gets built, one small step at a time. Each step is one commit and comes with something to learn. Steps marked **quota** make LLM calls through Kaggle's Model Proxy. They wait for an explicit go-ahead, and each one states its call count up front.

It's a chronological build log. "Decided", "Bias checks", and "Decisions" are kept current. Each step's *Found* records what was true at that step, so an early step can describe fewer models than there are now. For the results, see the [README](README.md).

## Goal

Measure how well LLMs generate random integers in [0, 99]. Each model answers hundreds of independent single-turn prompts, and its answers are checked for known biases: favoring primes, round numbers, and so on. Each check yields a sub-score in [0, 1]. The headline is the share of valid replies times the uniformity score (D8), and the other sub-scores show which biases lie behind it.

## Decided

- **Range:** integers 0–99.
- **Names:** there are two Kaggle Benchmarks (D15). The headline Benchmark, slug `randombench-overall`, holds only RandomBench Score and ranks the models by it. RandomBench Biases, slug `randombench`, holds the nine sub-score tasks. It was the first Benchmark, retitled, and a Benchmark's slug doesn't change with its title (4.9). A Benchmark is the page that groups tasks and shows the leaderboard. The collection task is RandomBench Draws, slug `randombench-draws`, and each scoring task follows that pattern (D10). The ten scoring tasks are RandomBench Score for the headline, then RandomBench Valid Answers, Uniformity, Primes, Multiples of 10, Multiples of 5, Favorite Number, Edges, Repeated Digits, and Last Digit, with slugs from `randombench-score` to `randombench-last-digit`. Valid Answers is the invalid-answer sub-score, named for the direction of its score: 1.00 means no reply was invalid. Benchmark and task slugs are both scoped to their owner (`/benchmarks/{owner}/{slug}` and `/benchmarks/tasks/{owner}/{slug}`), so nobody else can take ours and there's nothing to reserve early. Benchmarks are created on the Kaggle website; the CLI handles only tasks.
- **Calls:** single-turn, in a fresh conversation each time. No tools, and the model never sees its earlier answers.
- **Replies:** plain text for every model, read by one parser of our own (2.2). No structured output (`schema=`). kaggle-benchmarks 0.6.2 sends a schema natively to most models, but gemma, qwen, deepseek, and meta models get it only as text in a system message (`kaggle_benchmarks/kaggle/model_proxy.py`, lines 73–79). The models would then answer under different conditions, and their invalid-answer rates couldn't be compared. The prompt states the range, and an answer outside it counts as invalid.
- **Prompts:** six, in [randombench/prompts.py](randombench/prompts.py), each with a name, an author, and its text. D9 decides which prompt each draw gets. The checks pool a model's answers across all six prompts (D17).
  - **Ids:** a prompt's id is its name plus the first 8 hex digits of its text's SHA-256, such as `plain-47858739`. Editing the text gives a new id by itself, and a test pins every id, so no edit goes unnoticed, not even to whitespace. Once a prompt has been used in a run, it's never edited or deleted, and a change means adding a new prompt. A way to retire a prompt can wait until one first needs replacing.
  - **Authors:** Claude drafted all six (`claude-opus-5-5`). A prompt the maintainer rewords lists `benjaminbrumfield` instead.
  - **Style:** every prompt asks for a random integer, gives the range as 0 to 99 with both ends included, and asks for the number only. A model that wasn't asked to be random can't be faulted for having a favorite. No prompt gives an example number or names a bias, since either could steer the answer. Beyond that, the prompts differ in wording, tone, length, and framing, so no score depends on a single phrasing. A test checks the rules code can check.
- **Volume:** 600 draws per model per run. That gives a 95% margin of error of at most ±4 percentage points on any share a check measures, and 6 expected answers per value, above the usual minimum of 5 for a chi-squared test. Halving the margin would take 4× the draws. 600 also splits evenly across six prompts (D9). If the pilot shows spare quota, 1,200 is the next step up: ±2.8 points for twice the calls. The quota turned out to be $10 a day, and 600 draws on all six models cost $0.13 (4.3), so quota doesn't limit this. What it does limit is how many runs go at once. Model Proxy holds each call's maximum possible cost until the call finishes, and in 4.11 four runs at once got 1,006 calls refused. A second 600-draw run per model, for 1,224 in all, isn't needed (4.5a). Nano and gpt-oss-120b tie at 0.0327 ±0.0034 and 0.0325 ±0.0016, and a second run would narrow those intervals by only about √2. Every other pair of the first six is already apart. Gemini 3.8 Flash, added later, ties with both of them (4.8). The four costliest of the models added in 4.10 got 96 draws a run instead of 600 (4.11). In 4.11 the quota also refused 1,006 calls, which left Claude Sonnet 5.5 with 250 replies and GPT-5.6 Terra with 229. The refused calls weren't topped up (D3). Failed calls are recorded, not dropped, and a run that stops early keeps what it collected.
- **Raw data:** every raw response is stored. Parsed values and scores are always recomputed from the raw text, so a new bias check or a new parsing rule never requires calling the models again. [randombench/extract.py](randombench/extract.py) stores each Kaggle run as one JSON Lines file, `data/<model>/<run_id>.jsonl` (D5).
- **Parsing:** [randombench/parsing.py](randombench/parsing.py) reads a reply leniently on formatting and strictly on content (D4). Markdown, LaTeX, punctuation, and words are ignored. The numbers written in digits must all be the same integer, and it must be in 0–99. So `Sure! **47**.` is 47, and `47 or 52`, `3.5`, `47.0`, `100`, and `forty-seven` are invalid. A reply that restates the range, as in `from 0 to 99: 47`, holds three integers and is invalid too, because the prompt asked for the number only. If a provider puts its reasoning into the reply text, every number in the reasoning would count. 2.3 shows where reasoning ends up.
- **Invalid answers:** the rate of invalid answers is its own sub-score. A failed call, which returns no reply, doesn't count as invalid. With fewer than 2 valid answers, the other checks give no score (3.4).
- **Shared code:** a push uploads only the task file, so each task file holds a copy of the `randombench` modules it uses, refreshed by `python -m randombench.sync` (D6).
- **Leaderboard:** every sub-score and the headline appear on Kaggle, and no model is ever called twice for the same draw (D2, settled in 1.2). A notebook puts only one task on the leaderboard, and a dict result shows a blank Result. So the collection task makes each model's draws, and each score gets a scoring task of its own. A scoring task never prompts a model: run with `-m X`, it recomputes its score from X's stored draws and returns it. 1.2 showed that a task can be run against a model without prompting it. The scoring tasks are split across the two Benchmarks under "Names" (D15). The collection task is on neither, because its result is a draw count, not a score, and because a Benchmark row's run buttons would prompt models (4.9). The repo's own leaderboard page, `docs/index.html`, shows the same scores with models in rows and each score's interval, which the Benchmarks can't (5.3, D26, D27).
- **Temperature:** the provider's default. This was not our choice: kaggle-benchmarks 0.6.2 never sends temperature through Model Proxy (`kaggle_benchmarks/kaggle/model_proxy.py`, line 101). With temperature 1.0 sent explicitly, Gemini 3.1 Flash-Lite answered exactly as it does with none sent: 42 every time (2.4b, D16).
- **Seed:** `seed=None`, so providers sample freshly, as in normal API use. The library's default seed is 0, and it is sent to every non-Google model. A backend that honors seeds could then return the same number every time, which would look like a bias. GPT-5.4 nano accepted a null seed (2.3). The library never sends a seed to a `google/` model, so every Gemini and Gemma model samples freshly regardless. Claude Haiku 4.5 and gpt-oss-120b accepted a null seed in the pilot too, and both gave more than one answer (4.2), and so did Grok 4.6 and 4.7 (4.10).
- **Models:** 23, with their exact ids. The first seven are the first six (4.3) and Gemini 3.8 Flash (4.8). 4.10 piloted 17 more (D23), and 4.11 ran the 16 that worked: 600 draws for twelve and 96 for the four costliest. Grok 4.5 was dropped: the server lists it, but Model Proxy doesn't serve it (D24). Kaggle slugs come from `kaggle b t models`. The `llm.name` of each comes from the server's `LLMS_AVAILABLE` (1.3), and `MODELS` in [tasks/collect.py](tasks/collect.py) lists every model but Gemini 3.8 Flash (D12). The pilot confirmed the first six as runs' `llm.name` (4.2). Gemini 3.8 Flash's has labeled every creation run since 1.2. It was added in 4.7, and as the server's default model, its draws came from the creation runs of `randombench-draws` (D21). Once its draws were stored, it was taken out of `MODELS`, so a push prompts nothing (D23). Local runs reach the models in `LLMS_AVAILABLE` in `.env` (both checked 2026-11-14). Local development uses the first two.

## Bias checks

A perfect generator gives each value probability 1/100. Every check but the first scores only the valid answers, in [randombench/checks.py](randombench/checks.py). Each sub-score is in [0, 1]: about 1 for a perfect generator, and lower the more biased the model (D7). A gap is the share of answers that would have to change.

| Check | Sub-score | Ideal | Lowest | Perfect generator at N = 600 (mean, 95% range) |
|---|---|---|---|---|
| Invalid answers | 1 − the share of replies that aren't a single integer in [0, 99] (3.4) | 0% | 0 | 1 |
| Uniformity | The effective number of values K, as K/100. A fair pick among K values repeats itself as often as the model does | K = 100 | 0.01, one value | 0.991 (0.952–1) |
| Primes | 1 − the gap between the share of primes (2, 3, 5, …, 97: 25 values) and 25% | 25% | 0.25, all prime | 0.994 (0.965–1) |
| Round numbers | 1 − the gap from 10% multiples of 10, and separately from 20% multiples of 5 | 10% (20%) | 0.10 (0.20) | 0.996 (0.976–1), 0.994 (0.967–1) |
| Favorite number | 1 − the favorite's share above 1%, scaled so that 100% scores 0 | 1% | 0, one value | 0.996 (0.983–1) |
| Edges | 1 − the gap from 20% of answers in 0–9 or 90–99 | 20% | 0.20 | 0.994 (0.968–1) |
| Repeated digits | 1 − the gap from 9% of answers in 11, 22, …, 99 | 9% | 0.09 | 0.996 (0.977–1) |
| Last digit | The effective number of last digits K, as K/10 (7 is the usual suspect) | K = 10 | 0.10, one digit | 0.997 (0.983–1) |

Each sub-score estimates the model's true score with sampling noise nearly removed on average, so a model's expected score barely depends on its number of valid answers (3.3, 5.4c). [randombench/calibration.py](randombench/calibration.py) simulates any distribution at any N, and the tests use it to check that. Each score also has a 95% interval, from a bootstrap of the model's replies (D19).

The headline is the invalid-answer score times the uniformity score (D8). It's `None` whenever uniformity is, below 2 valid answers.

Some checks overlap. For example, 7, 17, 37, 47, 67, and 97 are all primes ending in 7. The headline uses only uniformity and validity, so an overlapping bias isn't counted twice. Uniformity already reflects every bias in the distribution, and the other checks show which ones lie behind it.
